===== Move child in same containment in same parent and replace existing child
Move <<existing-nodes, existing node>> <<MoveAndReplaceChildInSameContainmentInSameParent.movedChild>>
that’s initially at index <<MoveAndReplaceChildInSameContainmentInSameParent.oldIndex>>
within the <<MoveAndReplaceChildInSameContainmentInSameParent.containment>> inside <<MoveAndReplaceChildInSameContainmentInSameParent.parent>>
to the target index (<<MoveAndReplaceChildInSameContainmentInSameParent.oldIndex>> + <<MoveAndReplaceChildInSameContainmentInSameParent.indexOffset>>),
replacing <<existing-nodes, current child>> <<MoveAndReplaceChildInSameContainmentInSameParent.replacedChild>>{fn-org371} at the target index.{fn-org469}
<<MoveAndReplaceChildInSameContainmentInSameParent.replacedChild>> subsequently gets deleted, including all its descendants (including annotation instances).
This does NOT change references to any of the deleted nodes.{fn-org285}

This conforms to <<movingAndReplacingNodes, the action of moving a node and replacing another one in one specific list>> — see that section for more information, diagrams, and examples.
