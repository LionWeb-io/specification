===== Child moved in same containment in same parent and replaced existing child
<<existing-nodes, Existing node>> <<ChildMovedAndReplacedInSameContainmentInSameParent.movedChild>>
that was initially at index <<ChildMovedAndReplacedInSameContainmentInSameParent.oldIndex>>
within the <<ChildMovedAndReplacedInSameContainmentInSameParent.containment>> inside <<ChildMovedAndReplacedInSameContainmentInSameParent.parent>>
was moved by <<ChildMovedAndReplacedInSameContainmentInSameParent.indexOffset>> positions
to index (<<ChildMovedAndReplacedInSameContainmentInSameParent.oldIndex>> + <<ChildMovedAndReplacedInSameContainmentInSameParent.indexOffset>>),
replacing <<existing-nodes, current child>> <<ChildMovedAndReplacedInSameContainmentInSameParent.replacedChild>>{fn-org371} at the target index.{fn-org469}
<<ChildMovedAndReplacedInSameContainmentInSameParent.replacedChild>> subsequently gets deleted, including all its descendants (including annotation instances).
This does NOT change references to any of the deleted nodes.{fn-org285}

This conforms to <<movingAndReplacingNodes, the action of moving a node and replacing another one in one specific list>> — see that section for more information, diagrams, and examples.
