[[errors-move]]
==== Move errors

_MoveChild_ commands include:

* <<cmd-MoveChildFromOtherContainment>>
* <<cmd-MoveChildFromOtherContainmentInSameParent>>
* <<cmd-MoveChildInSameContainment>>
* <<cmd-MoveAndReplaceChildFromOtherContainment>>
* <<cmd-MoveAndReplaceChildFromOtherContainmentInSameParent>>
* <<cmd-MoveAndReplaceChildInSameContainment>>

_MoveAnnotation_ commands include:

* <<cmd-MoveAnnotationFromOtherParent>>
* <<cmd-MoveAnnotationInSameParent>>
* <<cmd-MoveAndReplaceAnnotationFromOtherParent>>
* <<cmd-MoveAndReplaceAnnotationInSameParent>>

_move from other parent_ commands include:

* <<cmd-MoveChildFromOtherContainment>>
* <<cmd-MoveAndReplaceChildFromOtherContainment>>
* <<cmd-MoveAnnotationFromOtherParent>>
* <<cmd-MoveAndReplaceAnnotationFromOtherParent>>

_same containment_ moves include:

* <<cmd-MoveChildInSameContainment>>
* <<cmd-MoveAndReplaceChildInSameContainment>>

_other containment_ moves include:

* <<cmd-MoveChildFromOtherContainmentInSameParent>>
* <<cmd-MoveAndReplaceChildFromOtherContainmentInSameParent>>

If we're trying to move a node in an invalid way, we report the following errors in the given order:

. <<err-unknownNode>> if:
** any of the involved nodes is unknown.

. <<err-invalidMove>> if:
** the moved node is a partition.
** the moved node is an annotation, and we use a _MoveChild_ command.
** the moved node is not an annotation, and we use a _MoveAnnotation_ command.
** the moved node is a child (or annotation) of the target parent node, and we use a _move from other parent_ command.
** the moved node is not a child (or annotation) of the target parent node, and we don't use a _move from other parent_ command.
** we use a _move from other parent_ command, and _old parent_ parameter is same as _new parent_ parameter.
** we use a _same containment_ move, and _old containment_ parameter is same as _new containment_ parameter.

. <<err-parentMismatch>> if:
** the moved node is not a child (or annotation) of the source parent node.
** the replaced node is not a child (or annotation) of the target parent node.

. <<err-indexEntryMismatch>> if:
** the moved node is a child in another containment of the same parent, and we use a _same containment_ move.
#TODO# or <<err-invalidMove>>?
** the moved node is a child in the same containment of the same parent, and we use an _other containment_ move.
#TODO# or <<err-invalidMove>>?
** the moved node is not the child (or annotation) at the given index in the given containment.
** the replaced node is not the child (or annotation) at the given index in the given containment.

. <<err-unknownIndex>> if:
** the index is < 0.
** the target parent contains less than the given number of elements in the given containment (or annotations).

. <<err-invalidIndexOffset>> if:
** the offset is 0.
** the offset is out of bounds of the given containment (or annotations) of the target parent.

[[err-invalidMove]]
===== Invalid move
Client tries to move a node incompatible with the emitted command.

.Technical name
`invalidMove`


[[err-parentMismatch]]
===== The given parent of a node is not its parent
Client provided an existing node N with a parent id in its parent property, but the node with this parent-id
does not have the existing node N as a child (annotation or containment).

.Technical name
`parentMismatch`


[[err-indexEntryMismatch]]
===== Entry at index is not the given entry
Client provided an entry (either a node or a target/resolveInfo) and an index, but the entry is not at the given index.

.Technical name
`indexEntryMismatch`


[[err-invalidIndexOffset]]
===== Index offset is invalid
Client provided an index offset which is either 0, or an integer such that a given “old” index + the index offset is not a valid index (in the list that’s the subject of the action triggering this error).

.Technical name
`invalidIndexOffset`


[[err-moveWithoutParent]]
===== Move without parent
Client tries to move a node that doesn't have a parent.

.Technical name
`moveWithoutParent`
